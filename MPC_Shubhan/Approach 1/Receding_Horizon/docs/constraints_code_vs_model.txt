================================================================================
 SCENARIO 1 - CONSTRAINT-BY-CONSTRAINT COMPARISON: CODE vs PDF
================================================================================
This compares what the Julia code (code/Scenario_1.jl) actually enforces against
what the source model "Optimization.pdf" specifies.

The controller is a MULTI-DAY, CROSS-DAY receding horizon: each 15-min window spans the
rest of today + `lookahead_days` future daytime blocks (global index g=(day-1)*n_day+k).
`n_days` reported days are simulated plus one dropped BUFFER day. Nights link the day-
blocks (MCS reset to full + parked at grid; CEV SOE + unfinished work carry over).

Cross-checked against the actual Optimization.pdf (equation numbers verified),
and against our plain-English/formal transcriptions
(docs/math_model.tex + docs/constraints_explained.txt).

Legend:  OK       = code matches the PDF exactly
         ADAPTED  = deliberate Scenario-1 adaptation (documented)
         ~OK      = matches up to a small, documented tolerance

SUMMARY OF THE ONLY REAL DEVIATIONS
--------------------------------------------------------------------------------
 1. (8a)/(10e) TWO-PHASE SPLIT - MCS energy-neutrality and "home by end" are
    closed overnight (Phase 2) rather than inside one 24h horizon. Deliberate.
 2. (8b) term_tol = 0.1 kWh - a tiny margin on the CEV terminal (exact at
    term_tol = 0). Recursive feasibility is guaranteed by the E7 keep-up reserve,
    so with term_tol = 0.1 both datasets run with ZERO infeasible/held windows.
 3. (12c) work is a PER-DAY SCHEDULE (work_by_day.csv), not one lumpsum: each
    reported day carries its own dig/load quota; unmet hours roll over.

CLOSED-LOOP CORRECTNESS: the rest rule (12e), precedence (12d) and pacing (13) are
seeded from the current day's applied history, so they hold ACROSS the 15-min
re-solves (no work-run leaking over a re-solve seam).

Everything else is enforced exactly as the PDF specifies (all HARD by default;
only missed-work 12c is soft, which is the PDF's own slack). The rest rule (12e)
is enabled with t_limit = 1 h.
