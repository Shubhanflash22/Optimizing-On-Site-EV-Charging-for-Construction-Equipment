================================================================================
 SCENARIO 1 (RECEDING HORIZON) - CONSTRAINT-BY-CONSTRAINT: CODE vs MODEL
================================================================================
Compares what the Julia code enforces against the formal model (math_model.tex /
the source "Optimization.pdf"). The window MILP is built in code/4_MCSModel.jl
(function build_window_model); the closed loop is code/5_MPCLoop.jl (run_mpc);
the entry point is code/7_Receding_Horizon_main.jl. The legacy standalone
code/Scenario_1.jl mirrors the same constraints but is NOT used by the main.

Controller: MULTI-DAY, CROSS-DAY receding horizon. Each 15-min window spans the
rest of today + `lookahead_days` future daytime blocks (global index
k = (day-1)*n_day + w). `n_days` reported days are simulated PLUS one dropped
BUFFER day. Nights link day-blocks: MCS reset to full + parked at grid; CEV SOE
and unfinished work carry over.

Legend:  OK = matches exactly   ADAPTED = deliberate, documented   ~OK = up to a tol.

THE ONLY DELIBERATE DEVIATIONS
--------------------------------------------------------------------------------
 1. (8a)/(10e) TWO-PHASE SPLIT - MCS neutrality + "home by end" are closed
    overnight (deterministic Phase 2) instead of inside one 24h MILP.
 2. (8b) DAILY REALIGNMENT + term_tol=0.1 kWh - the CEV terminal fires at every
    18:00 (each reported day energy-neutral), with a tiny margin that absorbs
    online-estimator drift (exact at term_tol=0, but that risks infeasibility).
 3. (12c) HARD "no working ahead" cap added on top of the soft cumulative target,
    so a day cannot borrow a future day's work (catch-up of leftover still allowed).

CLOSED-LOOP CORRECTNESS (modular code 4_MCSModel.jl / 5_MPCLoop.jl):
 - Rolling rules (rest 12e, precedence 12d, pacing 13) are seeded from the current
   day's applied Work/Break history, so a within-window limit can no longer "leak"
   work-runs across the every-15-min re-solves (the 8-in-a-row artefact).
 - The keep-up reserve (E7) is intended to make the daily CEV terminal (8b)
   recursively feasible.
 LATEST RUN (defaults: time_limit_sec=60, mcmc_samples=500, n_days=2 + buffer):
   * :input     -> 0 infeasible windows; missed work 0.00 h; loop ~53 s.
   * :synthetic -> 8 HELD/INFEASIBLE windows at the late-afternoon wind-down
                   (day 1 & day 2, k=37-40); missed work 0.00 h; loop ~1465 s.
 So on the synthetic scenario the hard daily terminal (8b) + keep-up reserve (E7)
 are NOT simultaneously satisfiable on the wind-down tail from the drifted state,
 and those intervals hold state (no fallback). Work still matches the per-day quota
 and no productive intervals are lost; the held windows are the k=37-40 tail only.
 FIX OPTIONS: tighten/relax the E7 reserve-vs-terminal interaction on the wind-down,
 or run with soft_term=true. (The Shrinking sibling runs 0 infeasible on both modes.)
