## ✅ NRP Storage Basics (from NRP docs)

On NRP (Nautilus):

* **PVC (PersistentVolumeClaim)** requests storage from the cluster’s storage system. A PV is dynamically provisioned when you create a PVC. ([NRP][1])
* You **mount the PVC inside your Pod**, and the data inside that mount **persists even after the Pod is terminated**. ([NRP][1])
* Typical storage uses the **rook-ceph-block** class by default. ([NRP][1])

> Note: Storage is *not suitable* for protected data (HIPAA, etc.) and may be cleaned up if not used for ~6 months. ([NRP][2])

# 🛠️ Step-by-Step

---

## ✔️ Step 1 — Create a PVC for Your Data

Create a YAML file `nrp-dataset-pvc.yaml`:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: resnet-data-vol
spec:
  storageClassName: rook-ceph-block
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 50Gi
```

Apply it:

```bash
kubectl apply -f nrp-dataset-pvc.yaml
```

Check status:

```bash
kubectl get pvc resnet-data-vol
```

It should be **Bound** — meaning the storage was provisioned. ([NRP][1])

---

## ✔️ Step 2 — Upload Your 30GB Dataset to the PVC

You can upload files into the PVC by creating a temporary “upload” Pod:

Create `dataset-uploader.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: dataset-uploader
spec:
  containers:
  - name: uploader
    image: ubuntu:latest
    command: ["sleep", "infinity"]
    volumeMounts:
    - mountPath: /data
      name: datavol
  volumes:
  - name: datavol
    persistentVolumeClaim:
      claimName: resnet-data-vol
```

Deploy it:

```bash
kubectl apply -f dataset-uploader.yaml
```

Copy files from your local machine into it (once only):

```bash
kubectl cp ./your_dataset_path dataset-uploader:/data/dataset
```
For monitoring upload in a new terminal
C:\Users\shubh> kubectl exec -it dataset-uploader -- bash
/# watch -n 5 du -sh /data/dataset
/# watch -n 5 "find /data/dataset | wc -l"

Now your dataset lives in the PVC at:

```
/data/dataset
```

📌 Stop and delete the uploader Pod after this:

```bash
kubectl delete pod dataset-uploader
```

---

## ✔️ Step 3 — Create Your Training Docker Image

Your image should contain:

* Python & GPU libraries (PyTorch)
* Training script
* Code to load from `/data/dataset` and write to `/data/outputs`

Example snippet in `train.py`:

```python
import torch
import torchvision
from torchvision import datasets, transforms, models
import os

DATA_ROOT = "/data/dataset"
OUT_ROOT = "/data/outputs"

transform = transforms.Compose([transforms.Resize(224), transforms.ToTensor()])
dataset = datasets.ImageFolder(root=DATA_ROOT, transform=transform)
loader = torch.utils.data.DataLoader(dataset, batch_size=32, shuffle=True)

model = models.resnet50(pretrained=False)
# add training logic…
os.makedirs(OUT_ROOT, exist_ok=True)
torch.save(model.state_dict(), os.path.join(OUT_ROOT, "resnet50_final.pth"))
```

Build & push to DockerHub (or NRP registry):

```bash
docker build -t yourhub/resnet50-nrp .
docker push yourhub/resnet50-nrp
```

---

## ✔️ Step 4 — Run the Training Pod

Create `nrp-train-pod.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: resnet-train
spec:
  containers:
  - name: trainer
    image: yourhub/resnet50-nrp:latest
    resources:
      limits:
        nvidia.com/gpu: 1
    volumeMounts:
      - mountPath: /data
        name: data-storage
  volumes:
  - name: data-storage
    persistentVolumeClaim:
      claimName: resnet-data-vol
```

Deploy it:

```bash
kubectl apply -f nrp-train-pod.yaml
```

Check logs while it runs:

```bash
kubectl logs -f resnet-train
```

---

## ✔️ Step 5 — Model Saving

Inside your training script, ensure you save to:

```
/data/outputs
```

This directory is inside the PVC, so **the model persists** even after the Pod stops.

---

## ✔️ Step 6 — Download the Model

You can **copy the model out** after training is done:

```bash
kubectl cp resnet-train:/data/outputs/resnet50_final.pth ./resnet50_final.pth
```

(or use another Pod that mounts the same PVC and exposes the files over HTTP, S3 or Jupyter)

# 🧠 Notes & Tips

### 📌 Storage Class

Most likely you’ll use:

```
storageClassName: rook-ceph-block
```

This is the default in NRP for PVC provisioning unless your admin tells you differently.

---

### 📌 Avoiding Uploads Every Run

Now that the dataset is in a PVC:

* You NEVER upload the full dataset again
* Your training Pod just **mounts the existing PVC**
* The Docker image stays **small** and reusable

---

### 📌 Where to Store Multiple Outputs

You can create **separate folders** inside the PVC like:

```
dataset/
outputs_epoch1/
final_models/
logs/
```

and mount them wherever you want in different pods.
